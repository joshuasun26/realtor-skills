# Listing Package — the orchestrator

Runs the listing skills in dependency order and hands back one package plus a schedule.

**Each step below is its own skill and can be run alone.** That is the point of the
split: an agent who only wants a flyer runs `listing-flyer`, and an agent who wants
everything runs this.

---

## The chain

```
listing-package
├─ 0. agent-profile          (only if profile/AGENT.md is missing)
├─ 1. listing-intake          → listings/<slug>/LISTING.md
├─ 2. listing-description     → MLS public + private remarks, short + hook
├─ 3. buydown-math            → listings/<slug>/BUYDOWN.md    [may BLOCK, see below]
├─ 4. listing-flyer           → flyer-standard.pdf (+ flyer-buydown.pdf only if step 3
│                                did not block)
├─ 5. listing-carousel (A)    → photo-led slides
├─ 6. listing-carousel (B)    → buydown slides                [skipped if step 3 blocked]
├─ 7. social-caption × N      → one caption per asset
├─ 8. compliance-check        → gate on everything above
├─ 9. source-check            → gate on every number above
└─ 10. schedule + handoff
```

## Running it

**Do step 1 completely before anything else.** Every later step reads `LISTING.md`, and
re-asking the agent for the square footage in step 4 destroys the whole impression of a
system that works.

**Step 3 is allowed to block, and blocking is a success.** `buydown-math` blocks if ANY
one of its five gate items is missing (dated rate sheet within 2 business days, the
pricing convention, a dated MI quote if MI applies, the full assumption set, or the
lender's NMLS ID) — a missing rate sheet is the most common trigger but not the only one.
When it blocks, for any reason:

- Skip steps 6 and the buydown flyer
- Deliver everything else
- Tell the agent in one line what is missing and give them the exact sentence to forward
  to their lender
- Do NOT estimate a payment to keep the package complete

**Steps 8 and 9 are gates, not reviews.** If `compliance-check` returns any `BLOCK`, the
package does not go out. Say that in your first line, then offer the fixed version.

## The schedule to hand back

Do not dump nine files and walk away. Give them a dated plan:

| Day | Piece | Where |
|---|---|---|
| Day 0 | MLS remarks live | MLS |
| Day 0 | Flyer printed | Listing, brochure box, office |
| Day 1 | Listing carousel | Instagram, Facebook |
| Day 2 | Buydown carousel | Instagram |
| Day 3-4 | Open house flyer + QR page live | If an open house is set |

**Never post the listing carousel and the buydown carousel on the same day.** They
compete with each other for the same audience and both underperform.

If there is an open house on the calendar, hand off to `open-house-package` rather than
duplicating its steps here.

## The handoff

Deliver as a list of file paths grouped by where each one goes, plus:

- What is blocked and why, in one line each
- What needs the agent's approval before it ships
- The one thing that would most improve the result (usually: better photos, or tagging
  and crediting the other agents involved)

If this is another agent's listing being marketed as a favor, tell them to send the
finished package to that agent **before** it goes live, framed as "made you something,
no charge, use it however you want." Finding it on the feed lands worse than receiving
it, and the relationship is the actual product.

## Ceiling

Two full packages a week is the realistic ceiling for one person, because each one is
real work and the value is in doing it well. Say so if the agent queues five.

## Self-improvement loop

Before ending a run of this skill, review the run:

1. Did any step fail, stall, or need a workaround you had to invent?
2. Did the user correct, reject, or rewrite something meaningful in the output?
3. Did you discover something a future run would want to know (a path that moved, a
   tool that replaced another, a preference they stated out loud)?

If yes to any, propose a specific edit to this SKILL.md in one or two lines and ask
whether to apply it. Propose only changes that would alter a future run's behavior --
skip cosmetic rewording, and never propose more than two edits at once.

Do not edit this file without their go-ahead. If they say no, drop it and do not re-raise
the same suggestion in a later run of the same session.
