# Carousel Render — the shared engine

Every carousel skill in this library calls this one to turn HTML into images. Kept
separate so the design rules live in one place and a fix reaches every carousel type at
once.

Reads `profile/AGENT.md` for brand.

---

## Dimensions

| Use | Pixels | Note |
|---|---|---|
| Feed portrait (**default**) | 1080 x 1350 | 4:5, the most screen space in feed |
| Feed square | 1080 x 1080 | Only if the agent asks |
| Story / Reel cover | 1080 x 1920 | 9:16 |

**Render at 2x and downscale.** Author the page at the target size, render at
`deviceScaleFactor: 2` (so 2160 x 2700), then resize to the target. Text and thin rules
come out dramatically cleaner than rendering at 1x.

## Method

1. One HTML file per slide, or one file with one `.slide` element per slide sized exactly
   to the target dimensions.
2. **All CSS inline. No CDN, no external font links, no remote images.** The render must
   work with no network. Embed images as files on disk or as data URIs.
3. Fonts: use the agent's brand fonts from `profile/AGENT.md` if they are installed
   locally. If they are not, **say so** and fall back to a named system stack. Do not
   silently substitute — the agent will notice on the third post and lose trust in
   everything.
4. Headless browser screenshot per slide, full element, no scrollbars.
5. Output `slide-01.png`, `slide-02.png`, … zero-padded, in post order, into the folder
   the calling skill specifies.

## The checks — run these every time

**Then open the rendered PNGs and actually look at them.** This is not optional and it is
where most failures are caught.

- **Overflow.** Long addresses, six-figure numbers, and long agent names break templates
  designed against short examples. Check every text box for clipping and for text
  escaping its container.
- **Bottom safe zone.** Nothing important in the bottom ~120px — the app's own UI covers
  it in feed.
- **Contrast.** Text over photography needs a scrim or a solid block. Check the worst
  slide, not the best one.
- **Minimum type size.** Body text no smaller than ~28px at 1080 wide; the disclaimer
  block no smaller than ~22px. Social compression destroys small type.
- **Consistent margins.** Inconsistent gutters between slides is the clearest visual tell
  of a generated deck. Check the left edge of all slides against each other.
- **Slide order.** Confirm the filenames are in the intended post order. Instagram uploads
  in filename order and a reordered carousel reads as broken.
- **File size.** Under about 8 MB per image. Larger gets recompressed harder by the
  platform and looks worse.

If any check fails, fix the HTML and re-render. Do not deliver images you have not looked
at.

## Reusability

Save the slide HTML alongside the PNGs, with the content separated from the layout where
possible, so next month's version is a data swap rather than a rebuild. Note the template
path in the output folder.

## What this skill does not do

It does not decide what goes on the slides, write the copy, or run compliance. The calling
skill owns all of that. This one turns approved content into correct images.

## Chains from

`listing-carousel`, `market-carousel`, and any future carousel type.

## Self-improvement loop

Before ending a run of this skill, review the run:

1. Did any step fail, stall, or need a workaround you had to invent?
2. Did the user correct, reject, or rewrite something meaningful in the output?
3. Did you discover something a future run would want to know (a path that moved, a
   tool that replaced another, a preference they stated out loud)?

If yes to any, propose a specific edit to this SKILL.md in one or two lines and ask
whether to apply it. Propose only changes that would alter a future run's behavior --
skip cosmetic rewording, and never propose more than two edits at once.

Do not edit this file without their go-ahead. If they say no, drop it and do not re-raise
the same suggestion in a later run of the same session.
