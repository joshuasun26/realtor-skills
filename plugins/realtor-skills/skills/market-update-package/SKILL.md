# Market Update Package — the orchestrator for the monthly cycle

The one recurring routine that makes an agent look like they have a system. It runs on the
calendar, not on a listing, which means it produces value in months when nothing else is
happening.

**Every step is its own skill and runs alone.**

---

## The chain

```
market-update-package
├─ 0. agent-profile          (only if profile/AGENT.md is missing)
├─ 1. market-pull  × area     → data/market/<area>-<YYYY-MM>.md    [may BLOCK]
├─ 2. market-brief × area     → email version, PDF version, 3-line text version
├─ 3. market-carousel × area  → 7 slides per area
├─ 4. social-caption          → caption per carousel
├─ 5. source-check            → gate on every number
├─ 6. compliance-check        → gate on all copy and all slides
└─ 7. stage the sphere send   → held for approval, never auto-sent
```

## Step 1 is allowed to block

If there is no MLS access this session, `market-pull` produces nothing and the whole
package stops. **This is correct behavior.** Do not substitute aggregator data, do not
reuse last month's numbers, and do not write a "qualitative" brief around the gap.

Report which areas pulled and which did not, and what you tried.

## Timing

Run in the **first week of the month**, for the month that just closed. Sales that close
late in a month take a few days to post in the MLS, so pulling on the 1st undercounts.
Waiting until the 5th or 6th gives a cleaner number, and the brief is still timely.

Use the **same area definitions** every month, read from the prior month's data file.
Changing the geography silently makes every trend claim false.

## Scale

Ask which areas up front. One area is a 20-minute run; twelve areas is a batch and needs
the same definition file reused and the same template re-rendered rather than redesigned.

If the agent wants more than about six areas, tell them plainly: six well-sourced areas
they can speak to beats twelve they cannot. Then build what they ask for.

## Step 7 — staging, not sending

Produce, and hold:

- The email to their sphere (brief, email version), with the recipient list filtered by
  `consent_tier` and every `optout` removed
- The three-line text version for the contacts who prefer text
- The carousel and caption ready to post

**Nothing sends and nothing posts without the agent's explicit go in this session, for
this specific batch.** Show them the recipient counts, the subject, and the copy. Approval
on this month's send is not approval on next month's.

## The handoff

Return:

- File paths grouped by destination
- The counts: contacts on the email list after filtering, contacts excluded and why
- Anything blocked, in one line each
- The single most interesting thing in this month's data, in plain language — the agent
  will use that line in conversation all month, and it is the real deliverable

## Archive

Never overwrite a prior month. `data/market/` accumulating twelve files is what makes
next year's year-over-year claims sourceable instead of asserted.

## Self-improvement loop

Before ending a run of this skill, review the run:

1. Did any step fail, stall, or need a workaround you had to invent?
2. Did the user correct, reject, or rewrite something meaningful in the output?
3. Did you discover something a future run would want to know (a path that moved, a
   tool that replaced another, a preference they stated out loud)?

If yes to any, propose a specific edit to this SKILL.md in one or two lines and ask
whether to apply it. Propose only changes that would alter a future run's behavior --
skip cosmetic rewording, and never propose more than two edits at once.

Do not edit this file without their go-ahead. If they say no, drop it and do not re-raise
the same suggestion in a later run of the same session.
